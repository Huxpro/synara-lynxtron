## How the matrix runs

`node scripts/comparison-cells.mjs` runs against one certified N1 run. It opens
each surface in both renderers and pairs every control that carries the same
accessible name. A control passes when its box is within 2 px of Electron's on
x, y, width and height. A matrix run covers the four configurations from a single
build: the first configuration builds, and the other three reuse
it with `--skip-build`. The harness refuses a stale bundle; that happened once,
when a source file changed mid-run, and the matrix was rerun.

A cell passes only when all of these hold:

- **Geometry:** every paired control is within 2 px or has a named exemption.
- **Coverage:** every control Electron names exists in Native under the same
  name, unless a coverage exemption explains the difference.
- **Page errors:** no page errors, and increment probes (the open popup or
  dialog) are within 2 px.

Two rules keep the pairing honest:

- **Open modals scope the page.** When an `aria-modal` dialog is open, only its
  subtree counts in both renderers, as for assistive technology. Native
  subtrees marked with Lynx's documented `accessibility-elements-hidden` are
  skipped.
- **Inputs are measured by their control box.** Both Input primitives put the
  accessible name on the inner field: Electron on `input[data-slot=input]`
  inside `input-control`, Native on `.LxInput` inside its wrapper. The harness
  measures the wrapper in both, replacing a per-label exemption.

## Named exemptions

Geometry (`NAMED_EXEMPTIONS`, plus the scrollbar rule):

- **Scrollbar gutter.** Electron gives overflowing panes a 10 px classic
  scrollbar, and Lynx overlays its indicator. Centred content shifts by half
  the gutter and right-aligned content by all of it, and nothing else changes.
- **Transcript trail ticks.** Native names the 56×10 hit row around each tick.
  The visible 6×2 tick sits at Electron's x/y.
- **Range sliders.** Electron's `<input type=range>` box is its 6 px track.
  Native names the 14 px thumb row centred on the same track.

Coverage (`COVERAGE_EXEMPTIONS`):

- **Settings sections, Git actions, Theme preference.** Electron names a
  landmark or group. Lynx has no landmark or group role, and the controls
  inside are compared directly.
- **Code theme.** Native's highlighter has fixed GitHub themes, so the select
  is hidden rather than offered as a no-op (39d4601c3).
- **Theme colours.** Electron's swatch opens a 2D picker popover. Native edits
  the hex value inline in the same swatch.
- **Toggle Sidebar.** Electron's closed right panel keeps an invisible 16 px
  rail on the window's right edge. Native opens the panel from the header
  toggle only.

**Correction to N3.** N3 attributed "produced no runtime events" to an
external provider stall. That message comes from a 15-second first-event
watchdog in `ProviderCommandReactor.ts`. The watchdog is part of uncommitted
work in the working tree, not in HEAD, and the harness runs the working tree.
On the failing turns the provider thread opened (`session/connecting`,
`thread/start` resolved), but no turn event arrived within 15 s; other turns in
the same session completed (J1 Electron, J6 both clients). Whether the silence
comes from the provider or from the uncommitted server change was not isolated,
because doing so needs a server built without that work. J1 and J2 passed on
earlier bundles the same day.

## Not verified here

- VoiceOver on Lynxtron. The names, hidden subtrees and modal scoping above
  are declared attributes; Lynx documents `accessibility-elements-hidden` for
  iOS, Android and Harmony, not desktop. This belongs to the N5 native checklist.
- Motion and pressed/focus states. The increments cover open states; hover,
  pressed and focus visuals remain in the fidelity contract.
