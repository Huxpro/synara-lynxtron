## Design Context

### Users

Synara is a desktop workspace for developers using coding agents such as Codex and Claude. Users spend long sessions reading transcripts, steering agents, reviewing tool activity, and switching between projects. The interface must stay legible, compact, and predictable while work is streaming or temporarily failing.

### Brand Personality

Calm, precise, and capable. Synara should feel like a polished native developer tool: quiet enough for sustained use, explicit about state, and responsive without decorative noise.

### Aesthetic Direction

Use the Electron renderer as the product and visual authority when matching Lynxtron. Preserve its restrained desktop composition, cool neutral palette, fine borders, subtle elevation, compact controls, and information density in both light and dark themes. Avoid generic AI gradients, oversized cards, ornamental motion, warm paper-like neutrals, and renderer-specific reinterpretations when a reference already exists.

### Design Principles

1. Match shared states exactly across Electron and Lynxtron: hierarchy, geometry, typography, icons, controls, motion, and copy.
2. Make asynchronous state unmistakable without making it loud; recording, processing, disconnected, and failed states each need distinct, stable feedback.
3. Optimize for long developer sessions with compact controls, strong alignment, minimal layout shift, and restrained color.
4. Use shared tokens and components before introducing renderer-local styling, while respecting Native platform constraints.
5. Preserve accessibility through semantic labels, adequate contrast, generous hit targets, keyboard behavior, and reduced-motion fallbacks.
