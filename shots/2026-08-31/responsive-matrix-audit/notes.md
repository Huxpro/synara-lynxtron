## Prioritized finding

- **High / Responsive fidelity:** the medium docked cell now has retained header and Electron expanded-state evidence, but Native transcript-list interaction remains unverified. This can hide an engine/input difference because the tier has more room than the 192px narrow chat pane while still activating compact header/composer policies and a 416px right dock.
- **Next acceptance cell:** `1000x700`, light, Terminal open, chat font 18px, long title, settled turn expanded through one tool detail. Both renderers must use one backend/thread and must retain header actions, bounded transcript width, reachable nested content, and a complete composer with `document.body.clientWidth === scrollWidth` on Electron.
- **Do not infer completion from narrower passing:** the narrow cell proves minimum-width containment, but not that Electron and Native switch responsive tiers at the same intermediate pane width.

## Native main-chat voice input result

- Capability boundary: Lynxtron 0.0.16 exposes no renderer microphone API. The production implementation therefore uses a macOS AVFoundation N-API host addon behind a platform bridge; unsupported desktop platforms remain capability-gated. Main chat alone enables the recorder, while landing and embedded sidechat cannot share or cancel it.
- Final exact-owned lifecycle cell: `864x620`, light, Terminal/right dock closed, backend `55246`, thread `lynx-landing-thread-1787254540864-987357febecef`, launcher `40182`, Native PID/window `46830/24061`. Runtime-pinned `main.lynx.bundle` SHA-256: `517dfa1f50db607e64ae6f2e25a763ada67d4c5e234775e88fb0de43d9f2a323`; `native/voice-recorder.node` SHA-256: `de04cc55c80cd0b21628804287292eabac4c2e042a7cf621b1811e09c3964dc4`.
- Real interaction: permission was already granted; Start rendered a duration counter and changing RMS waveform; Cancel returned to the mic and restored textarea focus; a second Start/Stop produced a 24kHz mono WAV and invoked `server.transcribeVoice`. The upstream request failed, and the final UI correctly rendered only `Outbound request failed.` rather than the nested RPC or provider-adapter envelope. Successful transcript insertion is therefore unit/contract-proven but not claimed as live upstream evidence.
- Close cleanup: a third recording was active when only the owned launcher was stopped. Both owned launcher and Native process exited; direct addon state afterward was `{supported:true, recording:false, permission:'granted', level:0}`. User launcher `97403` and forbidden PID `37522` were untouched. No screenshot was retained for this cell; Computer Use state inspection and host-call logs are the interaction evidence.
- Shared fix: `@synara/shared/composerPlaceholder` now owns the canonical placeholder and a width-aware empty-editor height policy. Electron and Native consume the same copy and line-count result. Native passes the actual post-dock pane width and chat font into `Composer`; the real textarea plus projected plain/token text receive the normalized chat size. Web reuses its existing composer `ResizeObserver`, including a hydration dependency fix so the observer attaches when secondary chrome first mounts.

Electron body remained `1000/1000`; its 288px form contained a 260x58.5px placeholder box at 18px/19.5px (`scrollHeight=60`, the 0.5px difference is browser rounding). Exact-owned Native PID/window `86790/22204` showed the same complete three-line prompt with the footer entirely below it and had a live socket to backend `53020`. Evidence: `electron-medium-composer-complete-final.png`, `lynx-medium-composer-complete-final.png`. Runtime-pinned bundle SHA-256: `d862fbecc39e7ea1058eecf61ada46669288bfb6b41a8f32560e4bbb02d214c9`.
